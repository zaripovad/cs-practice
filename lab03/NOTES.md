git diff показывает разницу между двумя состояниями

git show показывает изменения конкретного коммита и его метаданные

git log -S<строка> ищет коммиты, в которых изменилась указанная строка

git log -S поиск коммитов, где в файле появилось/исчезло слово "def"

git blame кто и когда менял каждую строку





git restore <файл> возвращает файл к состоянию индекса/коммита

git restore --source=<коммит> <файл> явно указывает, из какого коммита брать содержимое

Если бы были важные правки, которые хотели сохранить, git restore их перезапишет



git revert создаёт новый коммит, который отменяет изменения предыдущего, история сохраняется, а код возвращается к прежнему состоянию

git reset --hard удаляет коммиты из истории (перемещает указатель ветки назад)

В опубликованной истории это опасно так как у других людей будет конфликт при pull

Поэтому в общей истории безопаснее revert, а не reset



Тег — это постоянная метка на конкретном коммите, он не двигается, в отличие от ветки

Ветка — указатель, который перемещается на новые коммиты
